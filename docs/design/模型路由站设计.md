# 模型路由站设计（Model Router）

> 版本：v1（随 AppConfig v2 落地） · 更新：2026-10-16
> 目标：模型调用切换为「内部路由站 + 多供应商 + 故障转移 + CLI 原生降级」，API Key 永不硬编码，切换模型只改配置不改代码。

## 1. 总览

```
claude CLI（claude.exe，SDK in-process 驱动）
   │  ANTHROPIC_BASE_URL=http://127.0.0.1:<port>   模型名=虚拟别名（wb-opus/wb-sonnet/wb-haiku）
   ▼
内部模型路由站（主进程 http server，仅监听 127.0.0.1）
   │  ① 别名解析：wb-sonnet → 当前供应商的 sonnet 档真实模型名
   │  ② 故障转移：按 priority 选供应商，失败自动换下一家（429/5xx/网络错误）
   │  ③ 健康熔断：连续失败 N 次冷却 M 秒，到期半开试探
   ▼
供应商（Anthropic 兼容端点，base 不带 /v1）
   glm / deepseek / kimi / agnes / ark / 自定义…
```

两层降级，职责分离：

| 层 | 机制 | 触发条件 | 实现位置 |
|---|---|---|---|
| 供应商级 | 同档位换供应商重试 | 网络错误 / 429 / 5xx | 路由站（对 CLI 透明） |
| 模型级 | CLI 原生 `--fallback-model`（SDK `options.fallbackModel`） | 主模型过载/不可用 | CLI，别名驱动（wb-sonnet→wb-haiku） |
| 档位级 | 请求档位无可用供应商时向下退化（opus→sonnet→haiku） | 无供应商服务该档位 | 路由站 |

## 2. 配置结构设计

配置文件：`%APPDATA%/ClaudeWorkbench/config.json`（AppConfig v2）。密钥字段为 safeStorage（DPAPI）加密后的 base64，**明文绝不落盘**。

```jsonc
{
  "version": 2,
  "onboarded": true,
  "router": {
    "port": 0,                    // 0=随机端口；固定端口便于排查
    "localToken": "<随机生成>",     // 本地校验 token，防同机其他进程盗用路由站
    "retryOn429": true,           // 429 是否触发故障转移
    "timeoutMs": 120000,          // 上游首字节超时
    "circuitBreaker": { "failureThreshold": 3, "cooldownMs": 60000 }
  },
  "providers": [
    {
      "id": "glm",                          // 稳定 id，环境变量覆盖用
      "name": "智谱 GLM",
      "baseUrl": "https://open.bigmodel.cn/api/anthropic",   // 不带 /v1
      "apiKeyEnc": "<DPAPI 加密串>",         // 用户填写，禁硬编码
      "models": {                            // 三档映射
        "opus": "glm-5.3",
        "sonnet": "GLM-5.3-Flash",
        "haiku": "glm-4.5-air"
      },
      "defaultModel": "GLM-5.3-Flash",       // ANTHROPIC_MODEL 默认值
      "priority": 1,                        // 越小越优先
      "enabled": true,
      "maxContextTokens": 200000,
      "builtin": true                       // 内置预设标记
    }
  ],
  "workspace": {
    "defaultDir": "...",
    "permissionMode": "default",            // default/acceptEdits/bypassPermissions(红警)/plan
    "maxConcurrent": 2
  }
}
```

### 配置项说明

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `router.port` | number | 0 | 0=随机；固定值便于防火墙规则/排查 |
| `router.localToken` | string | 随机 | 路由站鉴权；CLI 侧由应用自动注入，用户无感 |
| `router.retryOn429` | boolean | true | 免费额度耗尽类 429 建议转移；付费限流可设 false 快速失败 |
| `router.timeoutMs` | number | 120000 | 上游超时（首字节）；流式长思考不受影响（socket 活跃即续期） |
| `router.circuitBreaker.failureThreshold` | number | 3 | 连续失败多少次熔断 |
| `router.circuitBreaker.cooldownMs` | number | 60000 | 熔断冷却；到期半开放行一次试探 |
| `providers[].id` | string | — | 稳定标识；环境变量覆盖名 = `CW_PROVIDER_<ID大写>_*` |
| `providers[].baseUrl` | string | 见预设 | 端点**前缀**：只填到域名/前缀一级，**不带具体端点**（anthropic 不带 `/v1`，openai 保留 `/v1`）；多余后缀会被 `normalizeBaseUrl()` 自动剥掉 |
| `providers[].protocol` | `'anthropic' \| 'openai'` | anthropic | 上游协议类型；决定拼接的端点路径、鉴权头与是否做协议转换 |
| `providers[].apiKeyEnc` | string | '' | DPAPI 加密后的 Key；空 = 该供应商不参与路由 |
| `providers[].models` | object | 见预设 | opus/sonnet/haiku 三档真实模型名；缺档自动向下取（sonnet 缺→defaultModel） |
| `providers[].defaultModel` | string | — | 该供应商的默认模型；别名解析兜底 |
| `providers[].priority` | number | — | 路由优先级，小者先试 |
| `providers[].enabled` | boolean | true | 关闭即跳过（key 保留） |
| `providers[].builtin` | boolean | true | 内置预设；id 不可改，其余字段用户可改 |

## 3. 环境变量配置（免改文件切换供应商）

所有配置均可被 `CW_` 前缀环境变量覆盖（优先级高于配置文件），适合 CI、分发预置、临时切换：

| 环境变量 | 作用 | 示例 |
|---|---|---|
| `CW_PROVIDER_<ID>_API_KEY` | 覆盖某供应商 Key | `CW_PROVIDER_GLM_API_KEY=sk-xxx` |
| `CW_PROVIDER_<ID>_BASE_URL` | 覆盖端点 | `CW_PROVIDER_GLM_BASE_URL=https://open.bigmodel.cn/api/anthropic` |
| `CW_PROVIDER_<ID>_ENABLED` | 启用/停用 | `CW_PROVIDER_AGNES_ENABLED=false` |
| `CW_PROVIDER_<ID>_MODEL` | 覆盖默认模型（同步写入 sonnet 档） | `CW_PROVIDER_GLM_MODEL=glm-5.3-flash` |
| `CW_PROVIDER_<ID>_PROTOCOL` | 覆盖协议类型 | `CW_PROVIDER_AGNES_PROTOCOL=openai` |
| `CW_ROUTER_PORT` | 固定路由站端口 | `CW_ROUTER_PORT=8787` |

ID 转换规则：大写、连字符转下划线（`my-relay` → `MY_RELAY`）。

### 4.1 协议类型（protocol）

CLI 只说 Anthropic Messages 协议，所以**路由站对上永远是 Anthropic**；对下按供应商能力分两类，写进配置再在界面上明示：

| protocol | 对话端点 | 模型列表 | 鉴权头 | 说明 |
|---|---|---|---|---|
| `anthropic` | `/v1/messages` | `/v1/models` | `x-api-key` + `Authorization: Bearer` | 直连透传，工具调用原生支持 |
| `openai` | `/chat/completions` | `/models` | `Authorization: Bearer` | 路由站做双向转换：tools/tool_choice 映射、tool_use ↔ tool_calls（流式按 index 累积 arguments）；不支持图片/文档块与 prompt caching |

baseUrl 只填「前缀」一级，端点由路由站按 protocol 拼接；`normalizeBaseUrl()` 会剥掉用户粘贴时常带的 `/v1`、`/v1/messages`、`/chat/completions` 尾巴（这是实际踩过的坑：拼成 `/v1/v1/messages` 直接 404）。设置页每张卡片都会显示「实际请求 POST <完整地址>」，不再靠猜。

## 5. 路由逻辑

1. CLI 请求到达 `POST /v1/messages`，本地 token 校验（`Authorization: Bearer` 或 `x-api-key` 匹配 `router.localToken`）
2. 取 `body.model`（别名或具体名）：
   - 别名 `wb-opus/wb-sonnet/wb-haiku` → 对应 tier
   - 其他值 → 原样透传（用户/CLI 直接指定）
3. 候选列表 = `enabled && 有 Key && 健康` 的供应商按 priority 排序；每家用 `models[tier] ?? defaultModel ?? models.sonnet` 解析真实模型名
4. 若该 tier 无任何候选 → 按 `TIER_DEGRADE` 向下退化（opus→sonnet→haiku）
5. 逐个转发：重写 `body.model` 为真实模型名，按 protocol 拼端点与鉴权头发往上游
   - anthropic：`baseUrl + /v1/messages`，流式 SSE 字节级 pipe
   - openai：`baseUrl + /chat/completions`，请求/响应双向转换，流式把 OpenAI SSE 翻译成 Anthropic 事件流（message_start → content_block_* → message_delta → message_stop）
6. 响应头阶段判定：先看状态码与错误体（见 5.1），可重试 → 换下一家；不可重试 → 原样透传（openai 协议的错误体会包装成 Anthropic 错误信封，避免 CLI 解析失败）
7. 200 响应不直接透传，先窥探首帧（≤8KB / ≤1.5s）：若首帧就是 error 事件则换下一家（此刻尚未向 CLI 写过任何字节，切换是干净的），否则把已窥探字节写给 CLI 后继续透传
8. 全部失败 → 503 + JSON 诊断（含每家失败原因）

### 5.1 故障转移判定：四类信号缺一不可

只看 HTTP 状态码会漏掉一半真实故障。判定实现在 `src/main/model-router/failure.ts`：

| 信号 | 处理 | 典型场景 |
|---|---|---|
| 状态码 408/409/429/500/502/503/504/522/524/529 | 转移（429 受 `retryOn429` 控制） | 限流、服务端错误 |
| 状态码 402 | 转移 | 欠费 / 套餐到期 |
| 错误体命中额度关键字（`insufficient_quota`、余额不足、欠费、arrears …） | 转移 | **国产厂商最常把欠费塞在 400/403 的正文里** |
| 错误体命中过载关键字（overloaded、rate limit、系统繁忙、并发 …） | 转移 | 上游扛不住 |
| 错误体命中客户端错误（invalid api key、model not found、unauthorized …） | **不转移**，原样透传 | 换一家也是同样的错，把原文给 CLI 更有诊断价值 |
| 网络错误（超时 / reset / DNS） | 转移 | — |
| 其余 4xx | 不转移 | 请求本身有问题 |

额度/配额关键字支持中英双语，因为智谱、DeepSeek、Kimi、火山方舟的欠费提示大量是中文。

#### 5.1.1 厂商业务错误码层（按 provider 注册）

状态码之外，`failure.ts` 还建了**厂商业务码表注册机制**（`PROVIDER_BUSINESS_CODES`），当前收录三家。两层动机：

1. **200 + SSE error 帧里没有状态码**——只有 `{"error":{"code":…,"type":…,"message":…}}`，业务码是唯一精确信号；
2. 部分厂商文案带 `${field}` / `${next_flush_time}` 模板变量，纯文本匹配不可靠；
3. 同一种 HTTP 码背后根因不同（阶跃 429 既是限流也是项目 Credit 上限；GLM 429 背后可能是欠费 1113），码表能把日志原因分清。

码表按 `providerId` 精确生效（别家的码/串一律不猜，仍走文本模式），判定原则与上表一致：

**智谱 GLM**（数字码，出处 [错误码](https://docs.bigmodel.cn/cn/api/api-code.md)）：

| 业务码 | 含义 | 判定 |
|---|---|---|
| 1113 / 1308 / 1310 / 1316–1321 | 欠费、使用上限（5 小时/7 天/周/月）、超额按量不可用 | **转移**（额度类） |
| 1309 / 1314 | GLM Coding Plan 到期、企业套餐失效 | **转移**（欠费类） |
| 1311 | 订阅套餐未开放该模型权限 | **转移**（换一家可能有） |
| 1302 / 1305 / 1313 | 速率限制、模型访问量过大、公平使用策略限流 | **转移**（过载类） |
| 1200 / 1230 / 1234 | API 调用失败、流程出错、网络错误 | **转移**（服务端） |
| 1000 / 1001 / 1003 / 1005 | 身份验证失败、缺少 Authentication 头、令牌过期、二次认证 | 不转移（Key 问题，透传原文） |
| 1220 / 1315 | 无权访问该 API、Key 仅限企业编程套餐 | 不转移（配置问题） |
| 1211 / 1212 / 1221 / 1222 | 模型不存在、调用方式不支持、API 已下线/不存在 | 不转移（模型名配置错） |
| 1210 / 1213 / 1214 / 1215 / 1261 | 参数有误/缺失/非法/互斥、Prompt 超长 | 不转移（请求本身有问题） |
| 1301 | 输入或生成内容含不安全/敏感内容 | 不转移（内容安全问题） |

**阶跃星辰 StepFun**（错误标识串放在 `error.type`，出处 [错误码](https://platform.stepfun.com/docs/zh/api-reference/error-codes)）：

| 错误标识 | HTTP | 含义 | 判定 |
|---|---|---|---|
| `insufficient_credit` | 402 | 组织 Credit 余额不足 | **转移**（额度类） |
| `project_credit_limit_exceeded` | 429 | 项目达到当期 Credit 上限 | **转移**（额度类，与限流同码不同因） |
| `member_project_credit_limit_exceeded` | 429 | 成员达到当期 Credit 上限 | **转移**（额度类） |
| `rate_limited` | 429 | 速率/并发超限 | **转移**（过载类） |
| `service_unavailable` | 503 | 服务负载过高 | **转移**（服务端） |
| `request_params_invalid` | 400 | 参数错 | 不转移 |
| `not_allowed` | 401 | 鉴权令牌缺失/无效 | 不转移 |
| `model_invalid` | 404 | 模型 ID 错或无权限 | 不转移 |
| （状态码 451） | 451 | 请求/响应内容未过审 | 不转移（全供应商通用状态码规则） |

**火山方舟 Ark**（错误类型串，出处 [突发流量错误码](https://www.volcengine.com/docs/82379/1848593)）：

| 错误码/类型 | HTTP | 含义 | 判定 |
|---|---|---|---|
| `ServerOverloaded` | 429 | 服务资源紧张 | **转移**（过载类） |
| `RequestBurstTooFast` | 429 | 请求量激增触发系统保护 | **转移**（过载类） |
| `TooManyRequests` | 429 | 限流类型名 | **转移**（过载类） |
| `PermissionDenied` | 403 | 模型未开通/无权限 | 不转移（配置问题） |

**DeepSeek / Kimi / Agnes**：官方错误码即 HTTP 状态码（DeepSeek 400/401/402/422/429/500/503；Kimi 400/401/403/404/429/500，其中 403 兼表余额不足），错误体为 OpenAI 风格 `{"error":{"message","type","code"}}`，无独立数字业务码——由状态码 + 双语文本模式覆盖（402→欠费转移；403+「余额不足」→转移；422→不转移）。

已知边界（官方明示）：流式调用若在推理过程中异常终止，不返回错误码而是在 `finish_reason` 里给原因——这属于「流已开跑」的协议固有限制，路由站无法中途换供应商（与 5.1 首帧探测的边界一致：只兜得住「尚未写字节」阶段的失败）。

### 5.2 切换供应商要不要重启 CLI

**不需要。** 三层都保证了热生效：

1. **路由站不重启**：配置变更后走 `reloadRouter()`——路由站的 `getConfig` 每次请求实时求值（普通模式直接读盘），所以只需让 `/v1/models` 缓存失效。不重启还有两个收益：端口不变、熔断计数不丢。
2. **端口不漂移**：`ensureRouter` 记住 `lastPort`，万一真发生重启也优先复用旧端口。这条是硬要求——CLI 进程启动时把 `ANTHROPIC_BASE_URL` 写进 env，端口一变，正在跑的长会话下一轮请求就会打到死端口上（ECONNREFUSED）。
3. **CLI 每次请求重建 env**：`chat:send` 每次调用都重新 `buildCliEnvOverrides(router)`，拿到的是当前路由站的 baseUrl 与档位。

所以「设置页改供应商 → 直接发下一条消息」即可生效，不用退出应用、不用重启 CLI、不会影响正在跑的会话（正在跑的那条仍用旧供应商跑完）。

熔断状态机：`closed →(连续失败≥threshold)→ open(冷却 cooldownMs) →(到期)→ half-open(放行一次) →成功→ closed / 失败→ open`。默认 `failureThreshold=3`、`cooldownMs=60000`。

### 5.3 切换可见化

故障转移发生时，路由站回调主进程，经 `stream:event`（domain=`router`）推给渲染层，对话台插一条琥珀色提示条：

```
↪ 故障转移：智谱 GLM（额度/余额不足）→ 已切 DeepSeek
```

同时写入 `%APPDATA%/ClaudeWorkbench/logs/router-<日期>.jsonl`，便于事后复盘哪家常挂。

## 6. 新增 / 切换供应商示例

### 6.1 配置文件方式：切换到 GLM-5.3-Flash 为主力

编辑 `%APPDATA%/ClaudeWorkbench/config.json`，确保 glm 在最前且 Key 已填：

```jsonc
{
  "providers": [
    { "id": "glm", "priority": 1, "enabled": true,
      "apiKeyEnc": "<在设置页填写 Key 后自动生成>",
      "models": { "sonnet": "GLM-5.3-Flash" }, "defaultModel": "GLM-5.3-Flash" },

  ]
```

其余供应商全部无 Key 时自动跳过；agnes 临时抽风时路由自动落到 glm，无需任何操作。

### 6.2 环境变量方式：一键切换（不碰配置文件）

### 6.3 新增一家自定义供应商（第 6+ 家）

### 6.4 获取供应商模型列表（填入 Key 后）

路由站聚合 `GET /v1/models`（60 秒缓存）：对每家可用供应商转发上游 `/v1/models`，合并返回 `{object:'list', data:[{id, provider, providerName}]}`。应用内设置页「获取模型」按钮即调用此端点；不支持该端点的供应商自动跳过。

## 7. 安全设计

- Key 只存在于：config.json（DPAPI 加密）或 `CW_PROVIDER_*` 环境变量；代码、日志、Git 中零明文
- 路由站仅绑定 `127.0.0.1` + 本地 token 校验，同机其他进程无法盗用
- 路由日志落 `%APPDATA%/ClaudeWorkbench/logs/router-YYYY-MM-DD.jsonl`，只记 provider/model/状态/耗时，不记请求内容与 Key
- `NO_PROXY=127.0.0.1,localhost` 自动注入 CLI 子进程，代理环境下回环不被劫持

## 8. 验证

- `npm run smoke:mock`：本地 mock 上游跑通全链路（exe→路由站→上游→SMOKE-OK），零外部配额，可重复
- `npm run smoke`：真实供应商端到端（需有效 Key；凭证来源见 README）
- `GET /healthz`：各供应商健康/熔断状态实时查询
