### 返工三项（厂长派单时的打回项，全部落地）
| 项 | 原实现的问题 | 修法 |
|---|---|---|
| handoff 带答案 | 旁路缓存 prompt→answer 精确匹配：用户编辑过输入框就失配，投送的会话里只有问题没答案 | 契约加可选 `answer`，渲染层直传；无 answer 的手打投送只写 user 一条（不写空气泡） |
| 热键降级链 | 写死 `Alt+Space`：Windows 上它是系统窗口菜单保留键，**本机实测注册失败**，用户按了没反应 | `Alt+Space→Ctrl+Alt+Space→Alt+Shift+Space` 逐个试，取第一个成功的；本机实测生效键 = **Ctrl+Alt+Space**；托盘加兜底菜单项；UI 显示真实键位 |
| 二进制下载 | `execFile+encoding:'utf8'` 会把 zip 非法字节替换成 U+FFRD（落盘成功、零报错、解压必失败）；`maxBuffer:16MB` 对 263MB 直接 ENOBUFS；且本机 gh 2.96.0 的 `gh api` **没有 `--output` flag** | 改 `spawn('gh')+stdout.pipe(createWriteStream)`，不设 encoding/maxBuffer；新增大小一致性校验（缺一字节即报「下载不完整」）；JSON 读取仍走原 utf8 runner（不能整体改二进制） |

### 踩坑记录（透明窗口的三个 Chromium 怪癖，均有实测证据）
1. **`visibilityState` 在 transparent 窗口 `show()` 后不更新**（始终 hidden，而主进程日志 `visible=true focused=true`）——可见性不能只信 visibilityState
2. **`hasFocus()` 在窗口自己 `hide()` 后不更新**（残留 true，与「刚 show 完」探针完全相同）——页面级信号无法区分「已收起」与「刚显示」，收起必须以主进程日志/isVisible 为准
3. **隐藏页定时器激进节流**：速聊页在阶段一期间 hidden，桩的 `setTimeout(900)` 被拖到秒级以上 → 自检假失败。改用轮询（CDP 求值不受页面节流影响）
4. 自检的 `Emulation.setDeviceMetricsOverride(760)` 与真实窗口宽 648 不一致 → 页面按 760 布局、右侧被窗口裁掉（「发送按钮被切一半」的假象）。**截 transparent 小窗不要 override 视口**
