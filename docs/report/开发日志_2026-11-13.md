### 真缺陷：`ship.mjs` 自动瘦身的伪成功

- **现象**：`ship.mjs:38` 用 `execFileSync(..., stdio:'inherit')` 调 `clean-releases.mjs --yes --keep=2`；后者在非交互会话回收站 API 不可用时**一项未删、实际释放 0 MB，却 exit 0**。发版日志因此显示「自动瘦身」，用户以为磁盘已释放，实际旧产物持续堆积（本次 dry-run 显示 638 MB 待清）。
- **根因**：脚本把「跳过」当成功路径，且没有可判定的结构化输出；`run()` 靠退出码判断，无法区分「已清理」与「全部跳过」。
- **修复**（`scripts/clean-releases.mjs`）：新增 `CLEAN_OK` / `CLEAN_INCOMPLETE` 结构化标记 + 可执行的下一步提示；**刻意不 `process.exit(1)`**——构建已成功，不能因清理失败反过来把发版判为失败（伪阻断）。
- **体验修正**：标记走 `console.log` 而非 `console.warn`。实跑发现 PowerShell 5.1 会把原生命令 stderr 包装成红色 `NativeCommandError` / `RemoteException` 异常块，看着像脚本崩溃。改为 stdout 后：`HAS_MARKER=True`、`HAS_PS_ERROR=False`、`EXITCODE=0`。
- **安全边界**：本次执行 `clean-releases.mjs --yes --keep=2`（不带 `--permanent`），3 个目录全部按约定跳过、释放 0 MB、未强删任何持锁文件。符合 AGENTS.md「AI 会话内永不静默永久删除」。
