# 规划快照：v0.2.x~v0.4 产品路线（2026-10-25 待老板拍板）

## 靶子定义（查证 2026-10）
Grok Bot（SpaceXAI，2026-08 发布）= 常驻智能体：消息式派活 → 云端电脑多步执行 → 交差回话；三件套 = 入口（全平台常驻）+ 多步任务执行 + 技能/连接器生态；语音（Grok Voice 3.0 端到端）、桌面控制（需逐次授权）、模板可分享。

## 我方底座映射
任务队列(M2)=执行器｜模板流水线(M3)=技能雏形｜会话/项目=记忆｜路由站=模型层｜桌宠+托盘=常驻入口｜权限Broker(M1)=安全闸。

## 五方案对比
| # | 方案 | 价值 | 成本 | 风险 |
|---|---|---|---|---|
| 一 | 底座：自动更新+多会话并行 | 低(工程高) | 中 | 低 |
| 二 | ClaudeBot MVP：热键速聊条+投递 | 高(日活) | 中 | 中低 |
| 三 | ClaudeBot 完全体：派活式智能体 | 最高 | 高 | 高 |
| 四 | 技能/插件平台 | 中高 | 高 | 中高 |
| 五 | 项目管理深化(IDE-lite) | 中 | 中高 | 中 |

## 厂长建议（待批）
- v0.2.0 = 方案一 + 方案二（自动更新 + 热键速聊 MVP）
- v0.3.0 = 方案三（派活式智能体：M2 升级为规划-执行-回话循环，M3 模板升级为可分享技能）
- v0.4.0 = 方案四（技能/插件平台，待技能=模板模式验证后固化 API）
- 方案五 随迭代穿插；语音输入放 v0.3.0+（先文本 MVP）
- 状态：等待老板拍板（一级决策）

## 补充分析（2026-10-25 凌晨）：Claude Code vs Grok Bot
- 同源不同形：内核同为 agent 循环（LLM+工具+权限+记忆），差异在驻留（按需会话 vs always-on）、环境（本地 vs 云端 VM）、交互（同步盯跑 vs 异步派活）、任务域（软件工程 vs 泛办公）、技能（文件配置 vs 演示学习）。
- 推论：M2 任务队列已是"半个 Grok Bot"，v0.3 本质 = M2 执行器从单轮 /v1/messages 升级为跑完整 claude CLI agent（权限 Broker + resume）。
- 差异化定位：ClaudeBot = 本地执行、数据不出机、面向开发者自动化（反打 Grok 的云端泛办公）。三步走计划不变且更清晰。
