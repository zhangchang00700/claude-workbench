## 2026-11-13 独立复验窗口隔离（流程自进化，二级自主）

- **触发**：qa 独立复验期间，厂长并行写入 4 个文件，导致其 C1「git status 应为空」断言 FAIL；不含单测口径正确率跌到 96.43%（未达 98%）。
- **根因**：把「写入型工作包」与「独立复验型工作包」排进同一时间窗，两者共享同一工作区快照。独立复验的前提是**快照冻结**，并行写入直接破坏前提。
- **新增排产约束**（流程细节，不触碰六道门禁标准）：
  1. 派出独立复验后，写入全部收口 → 一次 commit → 工作区干净 → 再通知 qa 按最终快照复验，并给出新 HEAD sha。
  2. 复验窗口内厂长不得再写任何文件；确需返工，先通知 qa 暂停并等新快照。
  3. qa 判 FAIL 就是 FAIL，**不得要求改判**；由厂长纠正流程后重跑，报告如实记录窗口污染时间线。
- **裁决原则**：子 Agent 的**原始数据**采信，但**归因结论**须由厂长对照架构事实裁决。本轮 qa 报 D2「latest.yml 缺失 → 自动更新失效」即属照搬 electron-updater 通用常识；实际本项目走 `gh api releases/latest`（src 中 0 处 import electron-updater），应降级为门禁文案失真。不盲信、也不盲驳，逐条给依据。
- **经验**：best-effort 步骤必须输出 `*_OK` / `*_INCOMPLETE` 结构化标记，且不能因「没做成」把已成功的构建判为失败（伪阻断）；CLI 提示走 stdout 避免 PS 5.1 stderr 红色异常块。
